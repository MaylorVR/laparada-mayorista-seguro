Ciclo de vida DevSecOps · herramientas y seguridad por fase

La seguridad se mueve a la izquierda (shift-left): cada fase tiene un control automático que bloquea el avance si falla.

#
Fase
Herramienta
Uso en el proyecto
Control de seguridad integrado
1
Plan
Jira Software (Scrum)
Backlog con 6 épicas y 24 historias, sprints, tablero Kanban
Historias de seguridad (HU04, HU05, HU06, HU09) y casos de abuso del caso (cupos, extorsión) como criterios de aceptación
2
Code
Git + GitHub, VS Code, ESLint
Ramas main / test / feature, commits convencionales, Pull Requests
Validación zod, SQL parametrizado, sin innerHTML, ESLint no-eval; revisión obligatoria vía PR
3
Build
GitHub Actions + npm ci
Instalación reproducible con lockfile, lint y verificación de build
npm audit (SCA) y Dependabot sobre dependencias y actions
4
Test
node:test + supertest
31 pruebas de integración con cobertura y reporte JUnit
Pruebas de seguridad: token manipulado, 403 por rol, inyección SQL, enumeración de usuarios
5
Release
Pull Request test → main
Solo se fusiona con el pipeline en verde
SAST con CodeQL y Semgrep, Gitleaks (secretos), dependency review
6
Deploy
Vercel CLI desde Actions
main → producción, test → preview, prueba de humo
Token en GitHub Secrets, JWT_SECRET y DATABASE_URL como variables cifradas, HTTPS + HSTS
7
Operate
Vercel Functions + Neon PostgreSQL
Serverless con escalado automático
helmet/CSP, rate limiting, roles de mínimo privilegio, TLS hacia la base
8
Monitor
Vercel logs, /api/salud, auditoría
Indicadores de negocio y salud del servicio
Tabla de auditoría, CodeQL semanal programado, alertas de Dependabot

Monitor retroalimenta Plan: hallazgos de CodeQL/Dependabot, denuncias y auditoría generan nuevas historias en el backlog de Jira.
